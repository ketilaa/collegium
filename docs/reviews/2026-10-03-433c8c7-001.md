### SEC-44-001: brreg.py's org-number regex is anchored with `^...$`, not `re.fullmatch`

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: injection
- Where: `src/collegium/acquisition/brreg.py:164` (`_ORG_NUMBER = re.compile(r"^\d{9}$")`), used at `brreg.py:199`
- Status: still open (deferred by the owner, not fixed)

`$` in Python's `re` (without `re.MULTILINE`) matches at the end of the string *or* just before a trailing `\n`, so a value like `"123456789\n"` would pass this check and then be spliced into `LANDING.format(org_number)`. The value comes from `data.brreg.no`'s own JSON (`hit.get("organisasjonsnummer")`), a fixed and trusted host, not from free text an outside party controls — so this is not exploitable today, only by brreg itself misbehaving, same risk profile as the still-open SEC-41 (NVA's `identifier`). Correctly deferred: this commit (433c8c7) appends it to CLAUDE.md's open-threads bullet, exactly matching how SEC-41 was deferred there (verified by reading that bullet directly). Per `docs/reviews/README.md`, RECOMMENDATION (LOW) does not require owner sign-off to not block a push; recording it for later batching with SEC-41's fix is good practice but not required for PASS.

**Fix:** Use `re.fullmatch(r"\d{9}", org_number)` (or anchor with `\A...\Z`) in place of `^...$`.
