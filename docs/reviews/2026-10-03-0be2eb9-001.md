### SEC-43-001: A goal's "program" label on the board does not show when that program is closed

- Severity: INFO
- Disposition: INFORMATIONAL
- Category: other
- Where: `src/collegium/web/templates/goals.html:12` (`{% if g.program %} · program {{ g.program }}{% endif %}`); `src/collegium/board.py:157-161` (`goals()` LEFT JOINs `programs` for the name only, not status)
- Status: new

This is intentional, documented behaviour (`docs/decisions.md`, 2026-10-01: closing "keeps its history... on record" and only "stops guiding *new* goals") — not a bug, and `memory.programs()` already excludes closed programs from what the Strategist sees for future planning (`src/collegium/memory.py:405-410`), so there is no risk of mis-planning. The only residual effect is cosmetic: an owner looking at `/goals` for a still-active goal whose program was later withdrawn sees only "program <name>" with no indicator that the program is closed, while `/programs` does show the status badge. Low value, not worth holding up this push.

**Fix (optional, non-blocking):** show the program's status next to its name on the goals page too (e.g. reuse the `status()` macro already used in `programs.html`).

## Specific checks requested

- **`withdraw_program`'s SQL and the `/programs/{id}/withdraw` route:** `owner.py:111-118` uses a fully parameterized `UPDATE ... WHERE id = %s AND status IN (...)  RETURNING name`; no string interpolation of untrusted data. The route (`web/actions.py:123-126`) uses the same `Acting` (`acting_as("owner")`) dependency as every other mutating route, and is covered by the app-wide `security_headers` middleware's same-origin check (`web/__init__.py:57-67`, `_same_origin`) and `TrustedHostMiddleware` — nothing route-specific needed and nothing missing relative to sibling routes like `/decisions/{id}/reject` or `/community/{id}/withdraw`. The CLI counterpart (`cli.py:76-84`) mirrors `_approve`/`_reject`'s use of `_board(settings).acting_as("owner")`.
- **The `_LABEL_LIKE_NAME` regex (`strategist.py:162`):** `^(new|p\d+(\s*\([^)]*\))?)$`, case-insensitive, applied to `plan.program.name.strip()`. Anchored on both ends, so it only rejects a name that *is* (not merely contains) "new" or "P<digits>" with an optional trailing `(...)`; a real title such as "New AI Regulations" does not match. The `[^)]*` group is bounded and cannot backtrack catastrophically — no ReDoS. On a match, `_propose_program` returns `None` before any `INSERT`, so neither the program row nor its decision is created — a fail-closed design matching the existing `_program_for` guard for goal labels. I could not construct a bypass (e.g. extra whitespace, a different bracket style, or a multi-word label containing "new") that still reaches the model's literal label text while evading the regex.
- **Stale state after closing a program:** `programs.status` already included `'closed'` in the CHECK constraint since migration 0001 (no new migration needed). Closing is a plain status UPDATE, auditable like every other table change (no deletion, history — decisions, linked goals — stays intact, satisfying the "no deletion, provenance kept" schema convention). `memory.programs()` filters out closed programs before showing them to the Strategist, so a closed program cannot be mistaken for open when checking overlap or assigning a new P-label. The one residual effect is the cosmetic goals-page issue noted in SEC-43-001 above (INFO, non-blocking).
