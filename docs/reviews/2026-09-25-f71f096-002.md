## Earlier findings

- **SEC-24-001 (HIGH, BLOCKING): fixed in 3e7105d.** I checked `_link_tags` (web.py:142-160):
  - **No mismatched positions.** `start` comes from `finditer` over `page`. `limit` is `min(start + 2000, len(page))`. Both `find` calls and the slice use `page`. No other copy of the page, lowercased or otherwise, is used for positions.
  - **Progress in every case.** A match covers `page[start:start+5]`, and none of those five characters is `<` or `>`. Every IGNORECASE variant is a single code point that is neither. So both `find` calls return `-1` or an index of at least `start + 5`. The match ends inside the page, so `limit >= start + 5`, and therefore `pos > start` always. `finditer` itself always advances.
  - **No overlap, and the `start < pos` guard never fires.** Any `<link` starting inside `(start, pos)` would be a `<` within the searched range, so `pos` would already be at or before it. The guard is harmless defence.
  - **Linear.** The IGNORECASE literal is tried at each position and fails within 5 characters, so it costs at most 5n. Accepted tags do not overlap and are at least 5 characters long, so there are at most n/5 of them. Each costs at most 2 × 2,000 characters of C `find`, and `find(">")` can scan the full 2,000 even when a `<` comes sooner. That is a constant of a few hundred per character, all in C. On 200 KB this matches the main session's 21 ms worst case for 40,000 bare `<link `. The slices add up to at most n characters.
  - **Attribute regexes.** `_FEED_TYPE` is linear. In `_HREF` (`\bhref=["']([^"']+)["']`), every attempt needs a quote right after `=`, and `[^"']+` stops at the next quote. The next `href=` attempt contains a quote itself, so the runs cannot pile up.
  - **IGNORECASE variants.** Python's Unicode IGNORECASE lets `i` match `İ` (U+0130) and `ı` (U+0131), and `k` match the Kelvin sign (U+212A). So `<lİnk`, `<lınk` and `<linK` (with the Kelvin sign) are also taken as tags. Each is a single code point, so the match is still 5 positions in `page`, and the progress argument holds. The only effect is a possible extra candidate that browsers would not treat as a `<link>`. It still needs a matching `type=` and `href=`, and the page's author could announce any feed with a real `<link>` anyway. The candidate is then fetched through the same SafeFetcher with the same limits. This does not matter.
  - **Tests.** They cover the 001 reproducer, the 1,000 × "İ" case, and finding a feed after 500 × "İstanbul ". A regression of the hang would make pytest hang rather than fail, because the timing assertion comes after the call. That is acceptable.
  - **Docs.** The docs/decisions.md entry describes SEC-24 and the hour it was deployed accurately.
