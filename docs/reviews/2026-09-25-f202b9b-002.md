### SEC-14-002: The bundle cannot show which paths or binary files any commit in the range contains

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: other
- Where: `scripts/security-review-bundle.sh:53-73`
- Status: new

`files.txt`, `diffstat.txt` and `tracked-files.txt` show only the net change and the current tree. A file that one commit adds and a later commit deletes appears in none of them. The secret scan runs `grep` over `git log -p`, which never sees the contents of binary files. That is how the swap file behind SEC-1 went unnoticed. In this iteration I could confirm its removal only from `.git/filter-repo/` metadata, which a future review cannot rely on.

**Fix:** Add two things to the bundle:
- every path touched in the range: `git log --format= --name-status $RANGE | sort -u`;
- a list of the binary files in the range, with `strings` output for each (or at least their paths and sizes).

### SEC-15-002: A required `POSTGRES_PASSWORD` does not change the password of an existing database volume

- Severity: INFO
- Disposition: INFORMATIONAL
- Category: config
- Where: `compose.yaml:7`; the `db-data` volume
- Status: new

The postgres image applies `POSTGRES_PASSWORD` only when it creates a new database. If the live volume was created while the default `collegium` still applied, the superuser keeps that password whatever `.env` now says. The same holds for the `collegium_*_app` logins until `logins` is run again. Now that the port is bound to 127.0.0.1, this exposes nothing to the network, and new installs are not affected.

**Fix:** If the live database was created with the default password, run `ALTER ROLE collegium PASSWORD ...` once, then `docker compose run --rm logins`.
