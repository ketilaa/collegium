### Verification detail (why no secrets-in-telemetry finding)

- **PsycopgInstrumentor**: `telemetry.py` calls `PsycopgInstrumentor().instrument()` with no kwargs, so `capture_parameters` defaults to `False` (confirmed in the installed library: `db.statement.parameters` is only set `if self._db_api_integration.capture_parameters`). The `db.statement` span attribute carries only the query *template* text, never bound values — so secrets, actor ids, run ids etc. passed as psycopg parameters never appear in a span. The codebase has no string-built SQL with secrets in it (the one dynamic-SQL case, `SET ROLE`, interpolates only a fixed role name via `sql.Identifier`). `PsycopgInstrumentor`'s connection-attribute capture is hardcoded to `{database, port, host, user}` — no `password` key, so the connection string's embedded password can never become a span attribute.
- **HTTPXClientInstrumentor**: the `http.url` span attribute goes through `redact_url()`, which strips URL-embedded credentials unconditionally and redacts a small fixed list of sensitive query-parameter names. Request/response headers are only captured if `OTEL_INSTRUMENTATION_HTTP_CAPTURE_HEADERS_CLIENT_REQUEST`/`_RESPONSE` are set — they are not, anywhere in this diff. Every adapter holding a credential (`tavily.py`, `llm.py`) sends it as an `Authorization: Bearer ...` header; the keyless adapters (`moltbook.py`, `searxng.py`, `nva.py`, `brreg.py`, `prh.py`) pass only non-secret values via `params=`. So under the defaults this commit ships, no API key or credential reaches a span attribute, whether or not the collector is ever enabled.
- Both instrumentors are only invoked inside `setup_telemetry`'s `else` (enabled) branch; with the shipped default `OTEL_SDK_DISABLED=true`, they are never even installed.
- **FastAPIInstrumentor**: default ASGI instrumentation captures route/method/status, not request bodies or query strings, so board form submissions are not captured as span data either.
