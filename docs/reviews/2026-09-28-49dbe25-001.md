### SEC-26-001: The pre-push hook checks only the net diff since the review, not every commit in between

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: other
- Where: `.githooks/pre-push:32-35`
- Status: new

`git diff --name-status "$reviewed" "$local_sha"` compares only the two trees. After a PASS, a commit that adds a file (a stray `.env`, a swap file) followed by one that deletes it, and then the report, shows a net diff of only `A docs/reviews/...md`: the push is accepted and the deleted file becomes public in history. Commit messages and identities after the review are not checked either. The same class of gap that SEC-14 closed for the bundle.

**Fix:** Check every commit, not the net diff: e.g. require `git log --format= --name-status --no-renames "$reviewed..$local_sha"` to contain only `A docs/reviews/YYYY-MM-DD-*.md` lines (or that no commit after the reviewed one touches anything else).

### SEC-27-001: The sensitive-terms scan does not look inside binary files or merge commits

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: privacy
- Where: `scripts/security-review-bundle.sh` (the terms scan and `binary-files.txt`)
- Status: new (a residual of SEC-16)

The terms scan reads `git log -p`, which prints "Binary files differ" instead of a binary's content and shows no diff for merge commits; the SEC-1 leak (a swap file holding a home path) was exactly this. `binary-files.txt` gives the reviewer printable strings, but only the first 40 per blob, and the reviewer cannot see the terms. Smaller: comment lines in the terms file are skipped only when `#` is the very first character, and non-ASCII terms in paths are missed because git octal-escapes such paths.

**Fix:** Also run the terms over all the printable strings of every binary blob, add `-m`/`--cc` to the `git log -p` call if merges can occur, and strip each line before the `#` test.

### SEC-28-001: The per-run paid cap can make a job repeat every hour, spending the daily budget without finishing

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: resource-abuse
- Where: `src/collegium/acquisition/__init__.py` (`_call`, and `discover` with a single named source); `src/collegium/worker.py` (budget deferral); `src/collegium/roles/scout.py`
- Status: new

`MAX_PAID_PER_RUN` raises `BudgetExhausted` although the daily budget is not spent. The fallback search, `extract` and `_enrich` catch it, but `discover` with a single named source does not: when a domain's discovery sources are exactly one paid source (only `tavily`) while the default search is free, the Scout's fourth paid call aborts the job, the worker finds budget left and defers it an hour, and the rerun makes the same three calls and is stopped again, until the daily budget is spent, and again when it reopens. The daily budget still bounds spend, but a configuration that worked before now wastes budget and produces nothing.

**Fix:** Make the per-run cap a distinct exception (or handle it in `discover`) so a capped run ends with what it has rather than being deferred; or skip the cap for a job whose only chosen source is paid. Add a test with `sources=["tavily"]` and more than three queries.

### SEC-29-001: Hostile PDFs and HTML pages up to 10 MB are parsed with no time limit

- Severity: LOW
- Disposition: RECOMMENDATION
- Category: resource-abuse
- Where: `src/collegium/acquisition/web.py` (`READ_MAX_BYTES`, `_read`, `_pdf`); `pyproject.toml` (`pypdf>=6`)
- Status: new

`_pdf` parses outside-chosen PDFs in the worker's only thread after the fetch deadline. pypdf has a long record of denial-of-service CVEs (decompression bombs, long loops on crafted cross-reference tables and content streams); its limits bound memory per stream, not the CPU time of `extract_text` over 30 pages. `READ_MAX_BYTES` (10 MB) also applies to HTML, so trafilatura now parses hostile HTML up to 10 MB where the limit was 3 MB. The same class as SEC-22. Mitigated by the lock pinning pypdf 6.19.0, pip-audit reporting nothing, and a parse error only making the page unreadable.

**Fix:** Keep 3 MB for text types and allow 10 MB only for `application/pdf` (the fetcher learns the type before reading the body); raise the floor to `pypdf>=6.19` so a re-lock cannot fall back to versions with known CVEs; consider a time limit on parsing, e.g. in a subprocess with a timeout.

## Earlier findings

- **SEC-8 (DNS rebinding): fixed.** `_check` stores the approved addresses in a per-fetch `pins` dict; `PinnedBackend.connect_tcp` connects only to those and refuses any host that was not checked, and refuses Unix sockets. httpcore takes SNI and Host from the URL origin, so TLS is still verified against the name; anyio does no lookup for an IP literal. Hosts that normalize differently in urlsplit and httpx (IDN) are refused, not left unpinned. `test_connections_go_to_the_checked_address_never_to_a_new_lookup` uses a rebinding resolver and would fail if the `_pool` replacement ever stopped taking effect (it depends on httpx internals; httpx 0.28.1 is locked). Side effect: with an explicit transport, httpx no longer honours `HTTP(S)_PROXY`, correct for SSRF protection and worth knowing operationally. Only `SafeFetcher` fetches outside-chosen addresses; feeds use it too.
- **SEC-21 (second lookup outside the deadline): fixed.** There is no second lookup; the only one runs in `_LOOKUPS`.
- **SEC-23 (robots.txt cached as allow-all): fixed.** Up to 5 redirects, each checked and pinned; 4xx means no rules (cached); 5xx, other statuses, errors, refused hops and running out of redirects are `UNREACHABLE` (not cached; the page is refused this time). Cancellation still skips caching. Tests cover an uncached 503 and a redirecting robots.txt.
- **SEC-12 (push-guard gaps): fixed as recommended.** The deny list covers abbreviated `--no-verify`, any `core.hooksPath`/`hookspath` change and `GIT_CONFIG*`; the wrong `-n` entry is gone. After a PASS only newly added `docs/reviews/YYYY-MM-DD-*.md` files are accepted (quoted unusual names fail to match, so they are refused). A GitHub ruleset blocks force pushes and deletion of main. Residual: SEC-26, and client-side routes a deny list cannot cover (editing `.git/config` or the hook, mixed-case keys, `bash -c` wrappers), inherent to a client-side self-discipline control.
- **SEC-14 (bundle lacks all paths and binaries): fixed.** `all-paths.txt` and `binary-files.txt` are produced. This range has no binaries, and every path it touched is in the net diff.
- **SEC-16 (history scan for sensitive terms): fixed in mechanism.** Case-insensitive, over contents, messages and identities, terms from an untracked local file, reported by number; it ran and found no hits. Residual gaps: SEC-27; see Not checked on the size of the list.
